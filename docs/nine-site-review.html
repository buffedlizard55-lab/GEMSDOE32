Why might H33-B2 have performed better?

The audited H33 file is sparse (37,654 dots). The code and historical lineage describe a B=2 catalogue-distance pruning of a related dot family. Under the requested distance-weighted Tversky metric, removing a redundant prediction can reduce false-positive mass without reducing the maximum kernel credit at a truth pixel. That can improve DTI. Conversely, removing useful coverage can lower DTI. Hidden labels are unavailable, so neither the causal contribution of pruning nor a future improvement over the unconfirmed 0.2778 can be established from the reported results alone.

The target is fault prediction relevant to geothermal exploration, not direct proof of a vent or viable reservoir. The official reference notebook uses ordinary Tversky training loss; it does not independently verify the 300 m scoring kernel. See the scientific review for evidence boundaries and ranked hypotheses.

How submission works once a candidate passes

  1. Run the shared feasibility, leakage, fold-local hide-and-recover, full-registry surface/final-dot and saved-byte gates. A paired spatial confidence interval must favor the candidate over the current best on the same evaluator.
  2. The separate selector checks the authenticated weekly cap and available slots. This review neither chooses a slot nor uploads.
  3. Only after release authorization, download the approved all-finite single-band TIF (or its single-TIF ZIP), check its displayed SHA-256, and choose it in the competition’s “File to submit” field. Use the approved unique name and note of at most 140 characters.
  4. Save the organizer receipt, submitted file hash and score. Only then label the result ORGANIZER-CONFIRMED.

These are future instructions, not authorization to upload any file currently linked here. The current weekly cap and leaderboard were not fetched; conflicting historical figures in the request cannot identify today's leader.
