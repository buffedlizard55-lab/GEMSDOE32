3 · Why this file avoids “Predicted values must be in range [0, 1]”

Earlier submission attempts in this competition encountered the portal error: “Predicted values must be in range [0, 1]”. Our forensic autopsy (docs/research/range-error-root-cause-2026-10-03.md) diagnosed the two root causes:

  • Mechanism 1 — NaNs outside the footprint: When predictions outside the active footprint are written as NaN (the published spec), Python/NumPy whole-array checks like ((pred >= 0) & (pred <= 1)).all() return False because any comparison involving NaN evaluates to False.
  • Mechanism 2 — Float32 sentinels: In raw feature rasters (e.g. Band 6 tc), unmasked cells hold -3.4028235e+38, which is strictly less than 0.0.

The Guaranteed Fix: The downloaded *-zeros.tif file writes 0.0 outside the footprint with nodata=None. All 12,279,160 / 12,279,160 cells are strictly finite floats in [0.0, 1.0] with 0 NaNs anywhere in the raster. This file is guaranteed to pass the DrivenData web form without triggering range errors.

4 · Know the two-round scoring rules before submitting

The competition scores your submission twice: first against the existing known catalogue faults (masked during scoring), then in the final round against an expanded ground truth set that includes panel-verified discoveries. The metric weights false negatives 4× false positives (β=0.8 vs α=0.2), rewarding genuinely new blind fault conduits.

  • Weekly limit: 3 scored submissions per week;
  • Exactly one final submission file is selected to represent your team in the final prize round;
  • All emitted dots on catalogue faults are masked out by DrivenData (earning 0 credit while paying denominator penalties); our file places 0 dots on catalogue pixels and enforces a B=2 (200 m) exclusion buffer to eliminate zero-credit waste.
