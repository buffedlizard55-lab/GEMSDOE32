## Important new finding: the current dot budget cannot satisfy the literal rule

The restored lattice is within 3 pixels of approximately 99.8713% of the footprint. After excluding known faults, only **6,514** allowed pixels lie outside that collar.

Let `U` be the number of allowed cells outside the collar, `N` the number of distinct emitted dots, and `O` the dots inside the collar. At most `U` dots can lie outside, so `O >= N-U`. The rule requires `O/N <= 0.70`:

```text
N-U <= 0.70N
0.30N <= U
N <= floor(10U/3) = 21,713
```

For the current **37,654-dot** budget the minimum possible overlap is about **82.7004%**, already over the threshold. No geological model or optimizer can overcome this pigeonhole bound at that budget. The shared `gems32.release_gate.dot_budget_feasibility` now computes it automatically. Tests cover the exact boundary using integer arithmetic.

This is a **necessary**, not sufficient, upper bound. A smaller emission may still fail other registry comparisons, minimum separation, geography, scientific quality, or leakage checks. Continuous/full-coverage references may be still more restrictive if their positive cells are interpreted as dots. We did not silently exempt a dense raster or dilute uniqueness by selecting only favorable references. Do not train a smaller model and assume it has passed.

## Shared-tool defects fixed

- **Silent thresholding:** the canonical binary writer and evaluator turned every positive float into `True`, so a tiny probability became a unit dot; negative/NaN values could disappear without an error. The binary emission contract now rejects nonbinary/nonfinite in-footprint values. Probability models must explicitly evaluate their emission step, not let file writing change predictions. The existing probability-preserving writer now rejects invalid inputs rather than clipping them; valid fractional values remain unchanged.
- **Invented missing metrics:** canonical writer defaults used `0.0` for unevaluated holdout metrics. They now use `null`.
- **Writer identity/metadata:** catalogue CRS/shape/transform must match the template; notes are checked **after** placeholder expansion; filename components cannot escape the output directory.
- **Cached registry corruption:** equal byte length previously allowed stale cached data to be attributed to a new commit. Cache reuse and downloads now require the pinned Git blob identity. Truncated Git trees cause failure, not incomplete success. Prefix/size coverage remains explicitly bounded.
- **Wrong-grid validation crash:** a shape mismatch previously reached footprint indexing and raised an exception instead of reporting a failed validation. It now returns a failed report; missing CRS cannot pass by comparing two `None` values.
- **Static evaluation overclaim:** the CLI explicitly marks static-mask and unproven NPZ provenance as non-promotable diagnostics. Being an NPZ does not prove fold-local training or feature derivation. The core shared hide-and-recover function rejects implicit probability binarization and incomplete OOF keys.
- **Stale executive page:** its H48 label pointed at an H49 file. The renderer now uses measured file-specific facts and suppresses its current-artifact link if its evidence no longer matches the registry/hash.

The metric algorithm and evaluator version were not changed; these are input/provenance guards, not a new scoring instrument. Earlier files are preserved, not retroactively given new performance results.
