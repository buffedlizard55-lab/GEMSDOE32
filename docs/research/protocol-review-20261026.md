### Protocol failures found

1. **Holdout leakage in candidate placement.** `scripts/run_round6.py` creates the candidate once using `dist_cat = distance_transform_edt(~labels)` from the complete label raster, then excludes pixels within the 2-pixel catalog buffer and passes this fixed mask to `evaluate_candidate_holdout`. `src/gems32/holdout.py` hides whole components when constructing cells, but its evaluator receives the already-fixed mask; it cannot reconstruct B=2 from only each fold's visible faults. Thus hidden catalogue geometry has already affected candidate placement. This directly violates the instruction to derive every catalogue-based feature from visible faults only. The resulting score is not an admissible hide-and-recover estimate and cannot authorize promotion.
2. **Even the descriptive holdout favors the incumbent.** `[HOLDOUT-DTI, leakage-affected/inadmissible; evaluator gems32.holdout draws 20/21; 22,232 withheld positives]`: candidate pooled DTI 0.0033763 [95% CI 0.0025124, 0.0045350], incumbent pooled DTI 0.0045154 [95% CI 0.0039433, 0.0052501]. These are separately bootstrapped intervals, not a paired difference interval. Because of finding 1, this is not a valid promotion result.
3. **Literal duplicate gate fails.** The Round-6 card reports 97.8169649971% of candidate dots within 3 px of `13gems_20261001_r13-lattice-s5_v2_nan-outside.tif`. Earlier R6 reporting exempted this calibration raster because it was dense. The session rule says *any registry raster* and states no density exception; therefore the literal final-dot threshold of at most 70% fails. A prior protocol audit in this repo already cautioned against a density exemption.
4. **Pre-placement all-registry surface check is incomplete.** The stored run compares against 29 detector rasters, but the calibration raster is absent from that surface comparison set. No surface correlation was measured against it; the required check cannot be called passed.
5. **Template matching passed on a pinned owner mirror.** `PYTHONPATH=src .venv/bin/python scripts/check_submission.py --strict-finite ...` passes against the restored sample. Sample hash `2176d08e…54d35cbc` matches the manifest; candidate has exact CRS/shape/transform, one float32 band, no nodata tag, and all 12,279,160 cells finite in [0,1]. The template is owner-mirrored, not organizer-authenticated.
6. **Historical status claims contradicted one another.** README and generated site pages advertised an unqualified green approval; duplicated hero panels and one incorrect portal name added confusion. The run card itself recorded an excluded lattice diagnostic, a holdout result below the incumbent, yet `verdict: promote` and `ok_to_download_and_submit: true`. Those are now corrected to `negative`/false, and the landing/site generator is fail-closed. Historical score values remain owner-reported: no organizer receipt in this repository binds exact bytes to those values.

No evidence here supports a claim that a new strategy beats 0.2778, 0.3195, or the separate 0.4413 snapshot.
