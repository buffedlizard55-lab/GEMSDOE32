# GEMSDOE32 reported score 0.2778: evidence and metric review

**Reviewed:** 2026-10-26 · **Competition:** DOE GEMS Prize, DrivenData #306
**Status:** corrected replacement for the superseded 2026-10-25 analysis. The old hidden-truth inversion and reachability estimates have been withdrawn; this document does not claim to reproduce an organizer score.

## Executive conclusion

The repository's historic portfolio record identifies `h33-h33-2-b2-20261004T220000Z-e5eb6e7e-zeros` (37,654 dots) as the source of the team's **reported** 0.2778. That attribution is **OWNER-REPORT**: this checkout contains no submission-page receipt linking the exact raster hash to that score. It is not a `HOLDOUT-DTI` result, and it is not independently `ORGANIZER-CONFIRMED` here.

The documented file lineage offers a plausible, limited explanation: successive sparse variants of the H19-5 field reportedly removed dots close to mapped-fault traces. If those pixels contribute little hidden-truth credit but still add false-positive mass, thinning can improve DTI. The available public record does not identify private truth, weighted TP, FP, FN, or the score effect of each individual edit. Therefore it does **not** prove that this mechanism caused the reported 0.2778, establish a universal thinning rule, or demonstrate an improvement over that result.

**Decision: DO NOT SUBMIT any new artifact based on this explanation.** A separate, compliant experiment with the prescribed shared holdout and all registry-uniqueness gates would be needed to support a promotion decision; the local source TIFFs and feature stack required for such a run are absent from this checkout.

## Correct metric algebra

For prediction mass `P`, hidden truth `G`, kernel credit field `k`, and `alpha=0.2`, `beta=0.8`, let `TP` be the kernel-weighted true-positive credit, `FP` the prediction mass not credited as TP, and `FN=|G|-TP`. Then:

```text
DTI = TP / (TP + alpha*FP + beta*FN)
    = TP / (alpha*(TP + FP) + beta*|G|)
```

For a general actual marginal addition with changes `ΔTP`, `ΔFP`, and `ΔFN`, with current denominator `D = TP + alpha*FP + beta*FN`, the addition improves DTI exactly when:

```text
ΔTP * D > TP * (ΔTP + alpha*ΔFP + beta*ΔFN)
```

There is a useful **special case**, not a universal threshold: for one binary prediction whose kernel credit `k` goes to a previously uncovered truth pixel, `ΔTP=k`, `ΔFP=1-k`, and `ΔFN=-k`, giving the break-even `k > alpha*DTI`. At reported DTI 0.2778 this idealized scalar is `k > 0.05556`. An addition to already partially-covered truth may have different marginal changes, so the actual condition above must be used. See [`src/gems32/metric.py`](../../src/gems32/metric.py), [`tests/test_metric.py`](../../tests/test_metric.py), and [`score-ceiling-analysis.md`](score-ceiling-analysis.md).

The earlier version of this note used a non-equivalent denominator simplification in an inversion, omitted terms in its rank comparison, and extrapolated hidden-truth/recall quantities. Those estimates, the stated score ceiling, and exact point requirements for reaching other scores are **withdrawn** and must not be reused as results.

## What the stored record does and does not support

- The archived portfolio history reports a sequence including 0.2600, 0.2708, and 0.2778, with decreasing pixel counts in a related family. These are **OWNER-REPORT** values; see [`registry/submissions.json`](../../registry/submissions.json) and [`registry/irregularities.json`](../../registry/irregularities.json).
- Historical byte-forensics records describe the B=2 raster as a sparse descendant of earlier H19-5 variants. That supports a lineage hypothesis, not score causality. Do not treat the archived counts or claimed score deltas as independently reproduced in this review.
- Existing local proxy, simulator, or holdout values are not leaderboard scores. A research result must be labelled `HOLDOUT-DTI` with evaluator version, withheld-positive count, and 95% CI. A live score can be labelled `ORGANIZER-CONFIRMED` only when a submission-page receipt is saved and linked to the exact submitted bytes.
- The public leaderboard is time-varying and concerns other teams' public entries, not this team's score. The official page read at `2026-10-26T04:32:28Z` showed #1 `xiaofanhu` at 0.4437; this observation is preserved at [`evidence/live_leaderboard_snapshot_20261026.json`](../../evidence/live_leaderboard_snapshot_20261026.json).
