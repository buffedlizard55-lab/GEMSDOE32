## 1. The metric is a budget, not a count

Official definition (page 967, reproduced in src/gems32/metric.py, verified to 1e-15 vs brute force):

```
k(d) = max(1 - d/R, 0), R=300m=3.0px
TP_p = sum_{p in P} p(x) * [1 - max_g k(d(x,g))]   // FP penalty weighted by proximity to truth
TP_w = sum_{g in G} max_{x:d(x,g)<=R} p(x) k(d(x,g))  // credit = best cover of each truth pixel
TP_w = (TP_p + TP_g)/2  // organizer's symmetric weighting (verified via dti_exact)
DTI = TP_w / (TP_w + 0.2*FP_w + 0.8*FN_w + eps)
     = TP_w / (0.2*(TP_w+FP_w) + 0.8*|G| + eps)  // identity proved in knowledge/02_the_ceiling...
```

`K=|G|` is common to all submissions in a round, so **leaderboard ranks T/(0.2F+0.8K)** and nothing else.

**Marginal bar theorem (verified in scripts/verify_theorems.py, 300 random trials sign-agreement 300/300):**

Adding one unit of mass at pixel x with realised kernel credit k = max_g k(d(x,g)) changes denominator by exactly **alpha=0.2** (dD = alpha*(dT+dF) = alpha*(k+1-k)=alpha), so:

```
dDTI > 0  iff  k*D > alpha*T  iff  k > alpha*DTI
```

At incumbent DTI 0.26, bar = 0.2*0.26=0.0520. At 0.2778, bar=0.0556. At leader 0.3262, bar=0.0652.

A dot pays for itself iff its marginal credit exceeds the current score's bar.
